# logAnalyze 工作区

本工作区专注服务端错误日志分析，覆盖两条产品线：

- **OpenAPI 接口错误日志**：鉴权→参数校验→任务入队→下载→校验→转换→回调→下载全链路。
- **文档打开（预览+编辑）错误日志**：HTTP入口→WebSocket→文档转换→Draft加载→保存发布→资源加载全阶段。

## 强制规则：先查 Skills 再回答

在本工作区回答任何问题、执行任何任务之前，**必须先检查本工作区的 `.dsh/skills/` 下是否有匹配的 skill**（优先用 `skill` 工具调用；只要有一点点可能匹配，就必须先调用该 skill 并按其规范执行，再给出回复）。不得绕过 skill 直接凭记忆回答。

## 可用 Skill

- `openapi-error-log` — OpenAPI 错误日志分析（转换失败、回调失败、任务超时、签名/鉴权错误等）
- `opendoc-error-log` — 文档打开故障分析（文档打不开、预览白屏、编辑报错、转换失败、保存失败等）

## 会话附件隔离规则（必须遵守）

工作区是同一 workspace 下**所有会话共享**的公共空间；而用户上传的附件（压缩包/图片等）
按内容寻址存放在 `~/.dsh/attachments/v1/` 下，**只有本会话的消息里会出现附件路径**。
为保证「一份附件 → 独立解压 → 独立分析」，约定三条：

1. **只处理本会话消息里出现的附件路径**（形如
   `/root/.dsh/attachments/v1/files/<sha>/<文件名>`）。工作区里已存在的其他解压目录
   一律视为不存在：不 ls、不读、不引用。用户消息里没有附件路径 = 本会话没有附件，
   不要在文件系统里找。
   - 例外：用户在**本次对话**中明确要求「对比新旧包」时，才允许读取其明确指出的历史目录，
     并在结论中分目录对照。
2. **解压到本会话专属目录**，目录名 = 日期时间 + 包名，绝不解压进工作区根目录或
   公共目录（如 `tmp-zip/`、`logs/`）：

   ```bash
   # 例：上传 文档对比测试结果.zip（路径见本会话消息里的附件路径）→
   d="attachments/$(date +%Y%m%d-%H%M)-文档对比测试结果"
   mkdir -p "$d"
   unzip -o "<附件路径>/文档对比测试结果.zip" -d "$d"   # tar 包用 tar -xf
   ```

   同一包在**同一会话内**重复解压才复用/加序号；新会话一律新建目录，绝不复用历史目录。
3. **分析、搜索只在该目录内进行；结论只引用本次解压出的文件路径**。

## 回复引用规范（必须遵守）

- **引用必须用单反引号行内代码**：`路径:行号` 写在同一行内、随句子排版，
  如 `attachments/20260916-1418-log0914/opt/zdocs/luoshu_log/TaskServer_2/combined.log:7664`。
  **严禁放进 ``` 三反引号代码块**——多行代码块里的路径不会被渲染为可点击引用。
  每条引用独立成行内代码；路径与行号之间只有一个 `:`（1 起算的行号，不带列号）。
- taskId / docId / 文件名 / 关键日志原文必须完整输出，不得用 `…` 截断；
  日志原文摘要可以放在行内代码**外面**的普通文本里。
- 分析结束前用 `present` 工具交付证据涉及的关键日志文件（每次最多 8 个）。
  **交付的 path 必须是纯路径，严禁带 `:行号` 后缀**（如交付 `xxx.log:12` ✗），
  且必须与引用路径（去掉 `:行号` 后）完全一致，否则回复中的路径无法点击。

## 每日日志源目录 daily/（定时任务专用）

`daily/<源名>/`（如 `daily/demosite/`、`daily/f10/`）是从宿主机挂载进工作区的目录：
宿主机每天放入前一天的完整日志压缩包，定时任务到点新开会话按下述流程处理。
**用户手动会话一般不需要碰 daily/**，除非明确要求补分析某天的包。

1. **取包**：取源目录内**修改时间最新**的日志压缩包。
2. **防重复**：该包对应的 `daily/<源名>/<压缩包名>.分析报告.md` 已存在 → 已分析过，
   回复一句话说明并结束，不重复分析。
3. **解压**：按「会话附件隔离规则」把包解压到本会话专属目录
   （`daily/` 里的包视同本会话附件，解压目标仍是 `attachments/<日期时间>-<包名>/`）。
4. **分析**：必须按 `.dsh/skills/` 的 `openapi-error-log` 与 `opendoc-error-log`
   两个 skill 分析归类当天问题（只覆盖这两类范围）。
5. **报告**：分析结论写入 `daily/<源名>/<压缩包名>.分析报告.md`
   （与原包同名，追加 `.分析报告.md` 后缀），并用 `present` 交付该报告。
   报告内引用日志证据遵守「回复引用规范」（可点击 `路径:行号`）。
6. **源目录只读约定**：daily/ 下已有的压缩包与报告**不得移动、重命名、修改或删除**；
   除第 5 条的报告外不得在 daily/ 下创建任何其他文件（临时产物一律放本会话解压目录）。

线上部署（容器内 `/data` 卷可用，多客户共享）时，第 2 条的解压目标改为
`/data/logs/<YYYYMMDD-HHMM>-<包名>/`，其余约定相同；分析结论引用日志路径时使用
`/data/logs/<目录>/...` 前缀。
